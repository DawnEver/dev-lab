# HPC: grants, shared accounts and remote verdicts

- **Two files, two owners.** The JOB file (`-c hpc.toml`, travels with the project) says WHAT runs: `[job]` entry/items/setup/workdir, `[cost]` of one item, `[policy]` for cutting. The MACHINE file says WHERE this box may run: the `[hpc]` table of `~/.config/lab-commons/config.toml` (`lab_commons.config`; `$LAB_COMMONS_CONFIG` overrides the path), holding its `workstation` name and one `[[hpc.grant]]` per share it holds. Partitions and QOS are cluster facts, so they live on the grant, not the job. A leftover `~/.config/lab-commons/hpc.toml` is refused by name: move it under `[hpc]`.

```toml
[hpc]
workstation = "lab-ws-07"            # stable, unique among boxes sharing an account

[[hpc.grant]]
user = "me"                          # ssh user; keys stay in ~/.ssh/config
hosts = ["login2.cluster", "login1.cluster"]   # login hosts of ONE cluster, tried in order
slurm_account = "acct-free"
cpus = 64                            # this box's share of the account's CPU quota
priority = 0                         # optional tie-break
partitions = ["shortq", "defq"]      # optional, in preference order
qos = { devq = "dev" }               # optional
```

- **An account is `(user, slurm_account)`; its hosts are doors.** Quota and the `lc:ws=` usage tags are per account. The runner tries each host with `ssh -o BatchMode=yes -o ConnectTimeout=10`; exit 255 (unreachable, the command never ran) fails over to the next host and logs it, and the first host that answers stays chosen. A command that ran and failed is NOT a failover. All hosts share Slurm and home, so `status`/`gather`/`retry` read back through any of them (`<job>.run.json` records the targets).
- **Many-to-many, refused by name.** A box may hold several grants; an account may be shared by several boxes, each with its own share. No `[hpc]` table, a duplicate account, an empty `hosts` or a non-positive share is refused with the file and the key named. No secrets in the file.
- **Usage is READ, never stored.** Every job carries `--comment=lc:ws=<workstation>`. The one-round-trip probe also runs `squeue -h --me -A <acct> -o "%C %k"` and sums CPUs per tag (an untagged job counts as someone else's). `--me` matters: a university free-tier account carries thousands of other people's jobs that count against nothing of ours.
- **Allocation is pure** (`plan.allocate`). Per grant: `headroom = min(share, quota - CPUs held by OTHER workstations) - CPUs held by this one`; plan on that headroom with the existing planner; take the grant whose plan finishes earliest (tie: higher `priority`, then file order). No headroom anywhere raises naming every account and why. `probe` prints, per grant, the shares known here against the quota and what each tag holds.
- **Verbs.** `python -m lab_commons.hpc {probe,plan,submit,status,gather,retry} -c job.toml`; `submit` records the grant it chose in `<job>.run.json`, so `status`/`gather`/`retry` go back to the same cluster.

## Remote verdict

`python -m lab_commons.hpc verdict --sha <40-hex> --repo-url <https> --install "<cmd>" [--collect "<pytest paths>"] [--select "<marker expr>"] [--python 3.13] [--repo <local repo>] [-c job.toml] [--history previous-record.json] -o record.json`

- Everything on the cluster lives under `~/ci/`: `cache.git` (bare, fetched read-only over HTTPS), `bundles/<sha>.bundle` (only when the commit is not on the remote: `git bundle ... --not --remotes` from `--repo`, base64 over the runner's stdin), `trees/<sha>` (a worktree with its OWN `.venv`, built once on the login node and reused), `bin/lab_ci_pytest_item.py` (the item runner, shipped from this checkout so its parser does not depend on the tested project's `lab_commons` pin). A day-to-day `~/<repo>` checkout is never touched.
- Node ids come from `pytest --collect-only -q` in the tree (`--select` and the platform expression join into ONE `-m`, since pytest keeps only the last); one item per test file. Each item runs `pytest <ids> -p no:cacheprovider -p lab_ci_pytest_item -q [-n 0]` -- the runner is also the pytest PLUGIN, and `-n 0` (when xdist is installed) keeps an item on its one CPU instead of starting a worker interpreter per file.
- **Outcomes are STREAMED, keyed by pytest's own `nodeid`.** The plugin appends one JSON line per test phase to `.lab-ci/<stamp>-r<round>/<item>.jsonl` as pytest reports it; the runner closes the file with `{"done": rc, "wall": s, "peak_mb": m}`. The verdict reads the streams (one `cat` per round), not the shards' end-of-run files. An xdist `@<group>` suffix is stripped back to the collected id. Measured on Ada (motronics 64c85da4d9, 2026-10-09): the junit file this replaced keyed on `(classname, name)`, `--dist loadgroup` had renamed grouped tests `<name>@heavy_parallel_0`, and 8786 tests that RAN were recorded `missing`.
- **A kill costs only the unfinished.** An item whose stream never closed (a shard Slurm killed for `TIMEOUT`/`OUT_OF_MEMORY`) keeps what it reported; its remaining ids are re-submitted split in halves, for up to `verdict.RETRIES` (2) more rounds, the next round asking for twice the memory after an `OUT_OF_MEMORY`. Only what is still unfinished after that is `lost`. Same run: 23 of 99 shards hit the 2h09 limit and 3 were OOM-killed at 6 GB, and the old atomic results file made all 13751 of their ids `lost`.
- **The plan is measured.** The record carries `durations` (seconds per id), `overheads` (per file: wall minus its tests -- interpreter and imports) and `peaks_mb` (per file). `--history <previous record>` feeds them back: an item costs its file's overhead plus its ids' durations, shards are packed consecutively by that time inside the `[policy]` window, the wall limit is the slowest shard's sum times `policy.safety`, and the memory is the worst measured peak times `policy.safety`. `[cost]` prices only files never measured, and each round's plan names them as `unmeasured`. Same run: a flat `seconds = 120` per file planned 129-min shards that ran 1h25-2h07.
- **Compute-node set-up is the grant's.** `setup = ["module load ..."]` in `[[hpc.grant]]` is prepended to every array task that grant submits, before the job's own set-up (Ada: `module load git-uoneasy/2.42.0-GCCcore-13.2.0` -- its compute nodes have no `git`, and 126 git-calling tests errored `FileNotFoundError: 'git'` on the same run).
- The record `{sha, platform, cluster, python, plan, rounds, outcomes, left, durations, overheads, peaks_mb}` is written to `-o` (`plan` is round 0's). Outcomes: `passed`, `failed`, `error`, `skipped`, `xfailed`, `not-covered` (a marker linux cannot run, by the platform table below), `lost` (unfinished after every retry), `missing` (its item's pytest closed without reporting it -- a crash mid-file, or an id the collection no longer yields). Only `passed` means passed. `left` maps each `not-covered` id to the platforms that CAN run it (`[]`: none).
- The tested tree's venv must provide `lab_commons.hpc.worker` (any `lab-commons` since the hpc tier); the array task runs `python -m lab_commons.hpc.worker` there.

## Platform parts: one verdict composed per platform

- ONE declaration, per marker, in the tested repo's pyproject, read AT `--sha` (`lab_commons.hpc.platforms`): `[tool.lab_commons.platforms]` `femm = ["windows"]`, `matlab = ["windows", "linux"]`. A marker not listed runs everywhere; platforms are `linux`, `windows`, `macos`. There is no `--not-covered` flag: the table is the one source.
- A part is named for the platform it RAN ON. The cluster record becomes the `linux` part: `python -m lab_commons.dev.platformparts record-linux record.json --tier <gate|heavy>` writes it into the verdict ledger, STRICTLY -- PASS only if every covered id is `passed`/`skipped`/`xfailed`; any `failed`/`error`/`lost`/`missing` is FAIL; a record covering nothing is refused. Its env names the cluster (`hpc:<cluster>:<platform>:python-<x>`), never the box that ingested it.
- A later part runs the ids its platform can run that no recorded part ran (`platformparts.to_run`), and records what it still `left`. A consumer exposes it as its gate runner's `--platform <name>`.
- Admission (`lab_commons.dev.admission`) accepts a whole verdict for HEAD OR the newest part per platform for HEAD whose `left` sets intersect to nothing. A FAIL part composes a FAIL (integration admits it and writes the gap; the trunk refuses). A missing part is refused naming the part and its command; an id no part ran, or that no declared platform can run, is refused by name. The trunk counts a composition only when every part is a PASS of a trunk tier.
